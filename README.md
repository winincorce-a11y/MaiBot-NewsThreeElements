# 新闻三要素

面向 MaiBot（MaiSaka）的文本生成插件：把一段随手写下的素材，改写成**一条新闻体短讯**，
并把指定人物的死讯自然地编入报道。默认生产维亚切斯拉夫·巴兰尼科夫，安东·尤丁采夫和尼基塔·布亚诺夫的死讯，可自定义名单。

> [!WARNING]
> 插件产出的人物死亡情节**全部是虚构的玩梗内容**，与现实中的任何个人、机构、事件无关。
> 默认不添加任何声明；如需对外发布，建议开启 `output.disclaimer` 并填写 `output.headline_prefix`。

## 功能概览

| 能力 | 说明 |
| --- | --- |
| 素材改写成新闻 | 输入任意素材，输出一段新闻通稿体短文 |
| 指定死亡名单 | 括号内写人名即替换默认名单；只写名单时素材取自被引用的消息 |
| 场景自适应身份 | 人物身份随新闻语境变化（战地 = 军官；事故 = 车间主管；赛事 = 教练） |
| 两种叙事模式 | 素材无死亡时用「转折」结构；素材已有死亡时改为「替换死者」 |
| 可选开头署名 | 可加「据○○社报道，」，且**按用户独立设置** |
| 统一结尾句 | 固定以「让我们为他们{词}🙏」收束，词从候选库随机抽取 |
| 多级降级 | 模型不合格自动重写 → 仍失败则用本地模板兜底 |

## 快速开始

### 要求

| 项目 | 要求 |
| --- | --- |
| MaiBot Host | ≥ 1.3.13（本插件在 1.3.18 上实测） |
| Plugin SDK | ≥ 2.7.0（`HomeCard` 与 `message.get_by_id` 的下限；实测 2.19.0） |
| Python | ≥ 3.10 |

### 安装

1. 将整个 `obituary-newsroom` 目录放入 MaiBot 的 `plugins/` 目录。
2. 启动或重载 MaiBot，插件首次加载时会自动生成 `config.toml`。
3. 在 WebUI 的插件管理页确认已启用（`plugin.enabled = true`）。

### 验证

```
/新闻三要素 美国大选
```

应在聊天中收到一条约 220 字的新闻短讯。

## 命令

### `/新闻三要素`

主命令。四种用法：

| 用法 | 示例 | 行为 |
| --- | --- | --- |
| 仅素材 | `/新闻三要素 美国大选` | 使用默认名单 |
| 素材 + 名单 | `/新闻三要素 美国大选 （特朗普，奥巴马，拜登）` | 名单替换 |
| 引用 + 名单 | 引用一条消息后发 `/新闻三要素 （张三，李四）` | 素材取自引用消息 |
| 重写 | `/新闻三要素 重写` | 沿用同一聊天流上一份素材 |

**名单写法**

- 用括号括起，全角 `（）` 与半角 `()` 均可
- 名字之间用中英文逗号、顿号、分号或空格分隔
- 取**最后一对**括号作为名单，因此素材自身可含括号
- 人数上限由 `people.max_people` 控制（默认 8）

**其他说明**

- 命令须出现在消息开头，允许前置 `@机器人` 与引用前缀（`Reply(...)`、`[回复了…]`）
- 支持全角斜杠 `／`
- 裸发 `/新闻三要素` 且无可取素材时，返回使用说明

### `/开头署名`

管理**自己的**新闻社名与开头署名开关，设置仅对本人生效。

| 用法 | 示例 | 行为 |
| --- | --- | --- |
| 设置名称 | `/开头署名 观察者报` | 之后自己触发的新闻以该社名报道 |
| 开启署名 | `/开头署名 开` | 新闻以「据○○社报道，」开头 |
| 关闭署名 | `/开头署名 关` | 不添加开头署名 |
| 查看 | `/开头署名` | 显示当前名称与开关状态及来源 |
| 重置 | `/开头署名 重置` | 名称与开关一并恢复全局默认 |

- 未设置过的用户**跟随全局配置**（`output.agency` / `output.lead_in`）
- 名称限制 20 字且不允许换行
- 数据保存在 `data/plugins/local.obituary-newsroom/user_agency.json`

## 运行逻辑

### 生成流程

```
素材
 ├─ 剥离引用前缀、抽取括号名单
 ├─ 判断素材是否已含死亡事件
 │    ├─ 否 → 常规模式：前半截素材延伸 →「值得注意的是」→ 后半截死讯
 │    └─ 是 → 替换模式：不另起转折，直接把素材中的死者换成名单成员
 ├─ 调用模型（最多 max_attempts 次，不合格自动重写）
 ├─ 质检：是否像思考链 / 是否漏人 / 是否分段 / 结构是否正确
 ├─ 收尾：剥离模型自写的「仍在调查中」类套话，换成统一结尾句
 └─ 发送：默认直发文本，被出站拦截时回退合并转发
```

### 两种叙事模式

| 模式 | 触发条件 | 结构 |
| --- | --- | --- |
| 常规 | 素材未提及死亡 | 前半段素材延伸 → 「值得注意的是」→ 后半段集中写死讯 |
| 替换 | 素材已提及死亡 | 顺着素材原叙事写，死因与场景沿用素材，仅替换死者姓名 |

判定依据为关键词匹配（`死亡`、`身亡`、`遇难`、`罹难`、`殉职`、`killed` 等）。

### 降级策略

1. 模型产出不合格 → 携带具体问题重写，最多 `generation.max_attempts` 次
2. 全部失败 → 使用本地内置模板生成（`fallback.enabled`）
3. 发送失败 → 直发文本被拦时自动改用合并转发

### 入口守卫

三个入口在执行前都会检查：

| 检查项 | 命令 | 工具 | API |
| --- | --- | --- | --- |
| `plugin.enabled` | ✓ | ✓ | ✓ |
| `only_platforms` | ✓ | —（拿不到 platform） | — |
| `blocked_stream_ids` | ✓ | ✓ | — |

工具与 API 由模型或其他插件触发，拿不到平台信息，因此平台限制只能由命令入口判断。

## 配置

配置位于插件目录下的 `config.toml`，也可在 WebUI 配置面板中修改（每项均有中文标签与说明）。

> [!IMPORTANT]
> 推荐通过 WebUI 修改配置。宿主只补齐缺失字段、**不覆盖已有值**，
> 手工编辑旧配置可能导致新增的默认值不生效。

### `[plugin]` 基础

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `config_version` | `1.0.0` | 配置版本，用于结构迁移 |
| `enabled` | `true` | 插件总开关 |
| `cooldown_seconds` | `20` | 同一聊天流的冷却秒数，`0` 为不限 |
| `only_platforms` | `[]` | 限定生效平台，空表示不限 |
| `blocked_stream_ids` | `[]` | 禁用的聊天流 ID 列表 |

### `[generation]` 生成

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `task_name` | `""` | 模型任务名（如 `utils` / `replyer`），空表示用默认任务 |
| `model_name` | `""` | 直选具体模型名 |
| `temperature` | `0.9` | 采样温度，新闻体建议 0.7~1.0 |
| `max_tokens` | `4096` | 单次生成上限（**含思考链**），开启思考的模型建议 ≥ 4096 |
| `target_length` | `220` | 期望正文长度（字） |
| `pivot` | `值得注意的是` | 常规模式的前后分界转折词 |
| `max_attempts` | `3` | 正文不合格时的最大尝试次数 |
| `extra_style` | `""` | 追加到提示词末尾的写作要求 |

### `[people]` 当事人

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `list` | 三人 | 默认死亡名单 |
| `max_people` | `8` | 名单人数上限 |

`list` 中每项字段：

| 字段 | 说明 |
| --- | --- |
| `name` | 姓名（必填） |
| `title` | 固定身份；**留空则由模型按场景现编** |
| `cause_hint` | 固定死因；仅本地兜底模板使用，留空则按场景生成 |

### `[output]` 输出

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `set_reply` | `false` | ⚠️ **必须保持 false**，开启会导致宿主丢弃整条消息 |
| `headline_prefix` | `""` | 标题前缀，如 `【虚构】` |
| `disclaimer` | `false` | 是否在末尾追加虚构声明 |
| `disclaimer_text` | 见配置 | 声明正文 |
| `max_chars` | `400` | 正文硬上限（字），超出按句号截断（结尾句不受限） |
| `forward_threshold` | `500` | 兼容保留；实际行为由 `delivery_mode` 决定 |
| `delivery_mode` | `text_first` | 发送方式，取值见下表 |
| `forward_nickname` | `盖金社` | 合并转发显示的署名 |
| `lead_in` | `false` | 全局默认：是否添加「据○○社报道，」 |
| `agency` | `盖金社` | 全局默认的新闻社名 |

`delivery_mode` 取值：

| 值 | 行为 |
| --- | --- |
| `text_first` | **先直发文本**，被出站拦截时才退回合并转发（推荐） |
| `forward_first` | 先合并转发（稳定绕过拦截，但显示为聊天记录卡片） |
| `text` | 只发文本 |
| `forward` | 只发合并转发 |

### `[ending]` 结尾句

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 是否由插件统一收尾 |
| `template` | `让我们为他们{verb}🙏` | 结尾模板，`{verb}` 为词位 |
| `verbs` | `["作哀","悼观","设敬","应敬","应悼"]` | 候选词，每次随机抽取一个 |
| `use_emoji` | `true` | 模板未含 emoji 时自动补 🙏 |

### `[fallback]` 本地兜底

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 模型失败时是否用本地模板 |
| `headline` | 见配置 | 兜底模板标题 |
| `org_name` | `有关部门` | 兜底模板中的通报机构称谓 |

## 实现说明

以下几条是维护这个插件时容易踩的坑，改代码前建议先看一眼。

### 引用消息的文本形态

引用一条消息发命令时，宿主会把引用段拼进 `processed_plain_text` 的**开头**：

```
Reply(target_message_id='1', target_sender='小王', target_content='...') /新闻三要素
```

这会影响两处：

- 宿主的命令匹配（`^/` 锚定）失败；
- 出站拦截插件也认不出这是命令，**不会建立命令豁免**，导致纯文本被当成闲聊取消。

因此插件通过前述两个 Hook 把前缀挪到命令之后。

### Hook 返回值格式

宿主 Runner 只读取 `modified_kwargs`，其它键会被**静默忽略**：

```python
# 正确
return {"action": "continue", "modified_kwargs": {"message": message}}

# 错误：不生效，且不会报错
return {"modified_message": message, "continue_processing": True}
```

### 被引用正文的键名

`raw_message` 的 `reply` 段中，正文键名在不同来源下不同，两种都要读：

- `target_message_content`（宿主序列化）
- `target_content`（部分适配器）

### 数组型工具参数

`ToolParameterInfo(param_type=ARRAY)` **必须**提供 `items_schema`，
否则宿主枚举工具时会抛出 `ValueError`，并连带拖垮整个聊天循环。

### `set_reply` 必须为 false

插件层拿不到被回复的消息对象。开启后宿主在 `SendService` 中会直接丢弃整条消息，
表现为「后台有日志、群里无反应」。

## 故障排查

| 现象 | 排查方向 |
| --- | --- |
| 命令无反应 | 确认插件已启用；命令须以 `/` 或 `／` 开头；检查命令管理页是否停用 `news_three_elements` |
| 后台有日志但群里无消息 | 检查 `output.set_reply` 是否为 false；检查是否被发言频率类插件拦截 |
| 输出的是推理过程/提纲 | 调大 `generation.max_tokens`（建议 ≥ 4096） |
| 引用后取不到素材 | 被引用消息可能无文字（图片、转发或已过期），日志会记录具体原因 |
| 正文被截断 | 调大 `output.max_chars` 与 `generation.target_length`，或减少名单人数 |
| 配置改动不生效 | 宿主不覆盖已有配置值，需手工确认 `config.toml` 中的对应键 |

## 兼容性

- 命令组件名 `news_three_elements` / `news_agency`，与用户可见的命令文本无关
- 用户数据文件格式 `{user_id: {name?, lead_in?}}`，**兼容旧格式** `{user_id: "名称"}`
- 插件 ID 固定为 `local.obituary-newsroom`，改命令名不影响已保存数据与启用状态
